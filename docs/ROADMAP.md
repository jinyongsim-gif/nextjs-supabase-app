## Phase 1: MVP 개발 계획

**목표**: 주최자가 이벤트를 만들고 초대 링크를 공유하면, 참여자가 로그인 후 자동 참여하고, 관리자가 이를 관리하는 전체 흐름 완성

### 1-1. 프로젝트 기반 설정

- [x] Next.js 15 + TypeScript + Tailwind CSS v4 환경 구성
- [x] shadcn/ui (new-york) 설치 및 공통 컴포넌트 추가 (avatar, dialog, form, select, skeleton, sonner)
- [x] ESLint, Prettier, Husky, lint-staged 설정
- [x] React Hook Form, Zod, Recharts 설치
- [x] Supabase 클라이언트 3종 구성 (server / client / middleware)
- [x] 라우트 구조 생성 (`(mobile)`, `admin`, `auth`)
- [x] 모바일 하단 내비게이션 / 관리자 사이드바
- [x] 타입 정의 (`lib/types`, `lib/schemas`)

### 1-2. 인증 및 권한 (F010, F011)

- [x] Google OAuth 로그인 (F010)
- [x] OAuth 콜백 / 이메일 확인 라우트
- [x] 프로필 설정 페이지 (`/auth/setup-profile`)
- [x] 프로필 조회/수정 페이지 (F011)
- [x] 관리자 로그인 페이지 (`/admin/login`)
- [ ] 관리자 권한 검증 (`role: admin`) 서버 측 점검 및 보강
- [ ] 로그인 후 초대 링크 복귀 흐름 점검 (join → login → join)

### 1-3. 데이터베이스 및 스토리지

- [x] `users`, `events`, `event_participants` 테이블 타입 정의
- [ ] 스키마 마이그레이션 파일을 저장소에 기록 (`supabase/migrations`)
- [ ] RLS 정책 점검 (주최자 수정/삭제, 참여자 조회, 관리자 전체 접근)
- [ ] 인덱스 확인 (`invite_code`, `created_by`, `event_id`, `user_id`)
- [ ] 중복 참여 방지 제약 (`event_id` + `user_id` unique)
- [ ] Storage 버킷 `event-covers` 및 접근 정책 점검

### 1-4. 주최자 기능 (F001~F003, F006~F009)

- [x] 커버 이미지 업로드 (F009)

- [x] 내 이벤트 목록 및 상태별 필터 (F007, F008)

## 작업 원칙

1. **작업 전**: 현재 코드 상태를 확인하고 이 문서를 먼저 갱신합니다.
2. **작업 중**: API / 비즈니스 로직은 Playwright MCP로 테스트합니다.
3. **작업 후**: `npm run check-all`과 `npm run build`를 통과시킨 뒤 체크박스를 완료로 표시합니다.
4. **Phase 순서**: Phase 1 완료 기준을 충족한 뒤 Phase 2를 시작합니다.
